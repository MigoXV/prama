## 修改边界

保留原版对齐、计分和同分路径选择；`bridge.c` 恢复 Python ctypes 所需 ABI，并提供逐条完成回调。回调位于 utterance 元数据补齐之后。

`runtime.c` 为每个结果追踪原生堆分配，为每次调用追踪打开的文件。正常释放、失败及取消均回收资源；报告采用单独的临时分配域。原生 `exit()` 被转换为当前线程的错误返回，发生跳转时由分配域统一清理，避免遗漏栈内局部对象。

可变静态数据使用 C11 线程局部存储，每次对齐或报告操作重置其缓存引用。结果持有自己的堆分配域，允许在生产线程结束后由其他线程读取和释放。统计常量表只读共享。Python 对同一个句柄的调用和关闭加锁；不同句柄可以并行工作。

其他必要修复：时间格式化使用 `ctime_r`；`rsprintf` 使用有界格式化；字符比较临时缓冲在调用内复用；长 speaker ID 缓冲扩容；拒绝倒置的 ID 括号；分配尺寸检查整数范围；词权重列遵循原版 CLI 初始化为 0。报告的编码和语言来自生成该结果的选项，不受其他调用影响。

## 构建和验证

在仓库根目录执行 `poetry run python build_native.py` 或 `poetry build`。构建脚本每次编译源码并原子替换库文件，不复用旧二进制。正常构建关闭 GNU diff 和 SLM，格式与选项限制见项目 README。

对照使用未修改的上游源码独立构建，禁止用修改后的库生成“预期结果”。线程检查包含同时停留在原生回调中的多个工作线程，并以单线程基准验证其报告。
